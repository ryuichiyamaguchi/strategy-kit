マスター雛形を Google Docs に変換する

テンプレート原本を Google ドキュメントに取り込む
Google ドキュメント

操作手順

  1. ブラウザで docs.google.com を開き、空白のドキュメントを新規作成します（白紙の Doc が開けば OK）。
  2. 開いた Doc のメニューバーから「ファイル → 開く」をクリックします。
  3. ダイアログ上部の「アップロード」タブをクリックします。
  4. ダウンロードした template_v3.0.md をダイアログにドラッグ＆ドロップする（または「ブラウザでファイルを選択」から指定する）と、アップロードと同時に Google ドキュメントへ自動変換されて新しいタブで開きます。
  5. 開いた Doc のタイトル（左上）をクリックして「テンプレート原本」に変更します。これがマスター雛形の正本になります。
  6. ブラウザのアドレスバーからこの Doc の URL をコピーし、どこかにメモしておきます（STEP 6 で使います）。最初に作った白紙の Doc は使わないので閉じて構いません。
テンプレート原本 Doc は「正本」です。直接編集しないでください。 案件ごとに「新規マスタードキュメント作成」から別の Doc を生成して使います。STEP 7 で実際に試します。

よくある詰まりポイント

「ファイル → 開く」のダイアログに「アップロード」タブが見当たらない
ダイアログ上部のタブが「最近使用したアイテム / マイドライブ / スター付き / 共有アイテム / アップロード」の順で並んでいます。一番右までスクロールしてください。
アップロード後に開いた Doc の文字が崩れている / 表が崩れている
直接ダブルクリックでアップロードしたり、ブラウザを別ウィンドウで開いていると、別アプリ（Markdown プレビューなど）で開かれる場合があります。Google ドキュメントの「ファイル → 開く → アップロード」経路でやり直すと正しく変換されます。
完了の確認: Google ドライブに「テンプレート原本」という名前の Google ドキュメントが存在し、その URL をメモできていれば STEP 1 完了です。

Apps Script で shim を準備する

作業用 Doc に GAS スクリプトを貼る
Google ドキュメント Apps Script
STEP 1 で作った「テンプレート原本 Doc」ではなく、別の新しい Google ドキュメントを作成します。この Doc が日常の作業起点になります。

操作手順

  1. Google Drive で「+ 新規 → Google ドキュメント → 空白のドキュメント」を作成します。名前は「STRATEGY-KIT 作業用」など任意でOK。
  2. 新規 Doc を開いた状態で、メニューバーの「拡張機能 → Apps Script」をクリックします。新しいタブで Apps Script エディタが開きます。
  3. ライブラリを追加します。 左サイドバーの「ライブラリ」の右にある「＋」ボタンをクリックします。
  4. 「スクリプト ID を入力」欄に、講師から配布された StrategyKitLib のスクリプトID を貼り付けて「検索」をクリックします。
  5. 「StrategyKitLib」が表示されたら、バージョン欄を「HEAD（開発モード）」に設定します（自動アップデートのため）。識別子は StrategyKitLib のまま変更しないでください。
  6. 「追加」をクリックします。左サイドバーの「ライブラリ」の下に「StrategyKitLib」が表示されれば成功です。
  7. 次に shim を貼ります。 ダウンロードした strategy-kit-v0.11.0-gas-shim.zip を解凍し、中の Code.gs をテキストエディタ（メモ帳・TextEdit など）で開きます。中身を全部コピーします（Cmd+A → Cmd+C）。
  8. Apps Script エディタ左サイドバーの「ファイル → Code.gs」をクリックして開きます。エディタ内を全選択（Cmd/Ctrl + A）して削除し、コピーした shim の中身を貼り付けます（Cmd/Ctrl + V）。
  9. 保存します（Cmd/Ctrl + S）。 エディタ上部のフロッピーアイコンをクリックしても保存できます。

よくある詰まりポイント

スクリプト ID を入力したが「StrategyKitLib」が出てこない
スクリプト ID のコピーミスが多いです。配布資料から再度コピーし直して試してください。ID の前後に空白が入っていないか確認します。
「拡張機能」メニューが見当たらない
Google ドキュメントのメニューバーは「ファイル・編集・表示・挿入・表示形式・ツール・拡張機能・ヘルプ」の順に並んでいます。スマートフォンからは表示されません。必ず PC の Chrome で操作してください。
完了の確認: Apps Script 左サイドバーに「StrategyKitLib」ライブラリが表示されており、Code.gs に shim のコードが貼られて保存されていれば STEP 2 完了です。

ウェブアプリとしてデプロイする

GAS に Web App URL を発行する
Apps Script Web App URL 取得

操作手順

  1. Apps Script エディタ右上の「デプロイ」ボタンをクリック →「新しいデプロイ」を選びます。
  2. 「デプロイの種類を選択」が表示されます。左にある歯車アイコンをクリックし、「ウェブアプリ」を選びます。
  3. 各設定を以下の通り入力します:
    • 説明: STRATEGY-KIT v0.11（任意ですが識別しやすくなります）
    • 次のユーザーとして実行: 「自分（your@gmail.com）」
    • アクセスできるユーザー: 「Google アカウントを持っているユーザー全員」← ここが重要
  4. 「デプロイ」ボタンをクリックします。
  5. 権限承認の画面が表示されます（次項の警告を参照）。承認を最後まで通してください。
  6. 「デプロイが完了しました」画面が表示され、ウェブアプリ URL（https://script.google.com/macros/s/...../exec という形式）が表示されます。この URL を必ずコピーしてメモしてください（STEP 5 で使います）。
「Google で確認されていません」警告が表示されます。これは正常です。
自分でデプロイしたアプリは Google が審査していないため、この警告が必ず表示されます。以下の手順で承認します:
  1. 警告画面下部の「詳細」をクリックします。
  2. 「（自分のアカウント名）に移動（安全ではないページ）」というリンクが表示されます。これをクリックします。
  3. 「このアプリが Google アカウントへのアクセスを求めています」画面で「許可」をクリックします。
  4. URL が表示されたらデプロイ完了です。

よくある詰まりポイント

「権限がありません」と表示される
OAuth 承認をスキップしたか、「詳細 → アカウントに移動」の手順を踏まなかった可能性があります。もう一度「デプロイ → デプロイを管理 → 最新バージョンを編集 → 再デプロイ」から承認をやり直してください。
「アクセスできるユーザー」で選択肢が少ない（Workspace アカウントの場合）
Workspace の管理者設定で制限されている場合があります。「自分のドメインのユーザー全員」でも動作します。個人 Gmail アカウントで試すのが最もトラブルが少ないです。
完了の確認: https://script.google.com/macros/s/...../exec の形式の URL をメモできていれば STEP 3 完了です。

Chrome 拡張機能を Unpacked で読み込む

Chrome に拡張機能をインストールする
Chrome 拡張機能
現在 Chrome Web Store への審査申請中のため、Day10 時点では「パッケージ化されていない拡張機能（Unpacked）」として手動で読み込みます。通常のインストールより手順が多いですが、難しくはありません。

操作手順

  1. ZIP を解凍します。 ダウンロードした strategy-kit-v0.11.0.zip をダブルクリックして解凍します（Mac は自動展開、Windows はファイルを右クリック →「すべて展開」）。デスクトップや「ダウンロード」フォルダに strategy-kit-v0.11.0 というフォルダが作られます。
  2. Chrome で新しいタブを開き、アドレスバーに以下を入力して Enter を押します:
Chrome アドレスバーに入力 
chrome://extensions/
  1. 拡張機能の管理ページが開きます。画面右上の「デベロッパーモード」のトグルをオン（青色）にします。
  2. 画面左上に「パッケージ化されていない拡張機能を読み込む」ボタンが表示されます。これをクリックします。
  3. ファイル選択ダイアログが開きます。STEP 4-1 で解凍した strategy-kit-v0.11.0 フォルダを選択して「開く」（Mac: 「選択」）をクリックします。フォルダの中に入らず、フォルダ自体を選択してください。
  4. 拡張機能一覧に「STRATEGY-KIT Helper」が追加されれば成功です。
Chrome 起動時に「デベロッパーモードの拡張機能を無効にしますか？」というポップアップが出ることがあります。
これは Chrome の仕様によるものです。「× でとじる（キャンセル）」をクリックしてください。「無効にする」を押すと拡張が停止してしまいます。毎回出る場合は、Chrome を起動するたびに × で閉じてください。

よくある詰まりポイント

「パッケージ化されていない拡張機能を読み込む」ボタンが表示されない
デベロッパーモードがオフになっています。画面右上のトグルを確認してオンにしてください。
フォルダを選択したがエラーになる
ZIP を解凍したフォルダではなく、ZIP ファイルそのものを選んでいる可能性があります。必ず解凍後のフォルダを選択してください。フォルダ内に manifest.json というファイルがあれば正しいフォルダです。
完了の確認: chrome://extensions/ の拡張機能一覧に「STRATEGY-KIT Helper」が表示され、エラーなく有効になっていれば STEP 4 完了です。

拡張機能のオプションに GAS URL を登録する

拡張と GAS をつなぐ設定を行う
Chrome 拡張 オプション設定

操作手順

  1. Chrome の右上にあるパズルピースのアイコン（拡張機能メニュー）をクリックします。一覧に「STRATEGY-KIT Helper」が表示されます。
  2. 使いやすくするために、STRATEGY-KIT Helper の横にあるピンアイコンをクリックしてツールバーに固定しておくと便利です（任意）。
  3. ツールバーの STRATEGY-KIT アイコン（またはパズルメニューの STRATEGY-KIT Helper）を右クリック→「オプション」をクリックします。
  4. オプション画面の「GAS Web App URL」欄に、STEP 3 でコピーした URL を貼り付けます（Cmd/Ctrl + V）。
  5. 「保存」ボタンをクリックします。「保存しました」などの表示が出れば成功です。

よくある詰まりポイント

右クリックしても「オプション」が表示されない
chrome://extensions/ を開き、STRATEGY-KIT Helper の「詳細」をクリック → 「拡張機能のオプション」リンクから開けます。
URL を貼り付けて保存したが接続できない
URL の末尾が /exec で終わっているか確認してください。/dev 末尾の URL は開発用で受講者環境では動作しません。STEP 3 で「新しいデプロイ」から取得した URL を使ってください。
完了の確認: オプション画面の URL 欄に https://script.google.com/macros/s/...../exec が入力されて保存できていれば STEP 5 完了です。

テンプレート原本を登録する（初回のみ）

コピー元の Doc を STRATEGY-KIT に記憶させる
Google ドキュメント 初回設定

操作手順

  1. STEP 2 で作成した「STRATEGY-KIT 作業用」の Google ドキュメントを開きます（Google Drive から開く）。
  2. ドキュメントを開いたら、ブラウザのタブを一度閉じて開き直します（または F5 / Cmd+R でリロード）。これをしないとメニューが反映されません。
  3. メニューバーを確認します。「ファイル」「編集」... の右側に「STRATEGY-KIT」というメニューが追加されているはずです。
  4. 「STRATEGY-KIT → テンプレート原本セットアップ（初回のみ）」をクリックします。
  5. ダイアログが表示されます。STEP 1 でメモしておいた「テンプレート原本 Doc の URL」を貼り付けて「OK」をクリックします。
  6. 「テンプレート原本を登録しました」のようなメッセージが表示されれば成功です。
テンプレート原本 Doc を直接開いた状態で「テンプレート原本セットアップ」以外のメニューを実行しないでください。 テンプレートが上書きされるリスクがあります。日常の操作はすべて「作業用 Doc」から行います。

よくある詰まりポイント

メニューバーに「STRATEGY-KIT」が表示されない
ブラウザのタブを完全に閉じて開き直してください。リロードだけでは反映されないことがあります。それでも出ない場合は、STEP 2 で shim が正しく保存されているか確認してください（Apps Script エディタを開いて Code.gs の中身を確認）。
メニューはあるが「テンプレート原本セットアップ」を実行するとエラーになる
「StrategyKitLib is not defined」の場合は STEP 2 のライブラリ追加に戻ってください。「権限がありません」の場合は STEP 3 のデプロイで OAuth 承認が完了しているか確認してください。
完了の確認: 「テンプレート原本セットアップ（初回のみ）」が正常に実行され、成功メッセージが表示されれば STEP 6 完了です。

新規案件を作成して動作確認する

実際に戦略マスター Doc を自動生成する
動作確認 完了

操作手順

  2. 業種選択ダイアログが表示されます。「B2C（一般消費者向け）」または「B2B（法人向け）」を選択して「OK」。

Gemini API 設定（任意）

全自動・半自動モードで AI に文章を書かせる場合のみ必要です。手動で使う場合はスキップできます。

📘 初めての方は完全ガイドを推奨
「API って何？」「Google AI Studio と Google Cloud の違いは？」など、IT 用語ゼロから理解できる詳細ガイドを用意しています。
Gemini API 完全ガイドを開く

API キーの取得（簡略版）

  1. Google AI Studio（aistudio.google.com/app/apikey） を開き、Google アカウントでログインします。
  2. 「API キーを作成」をクリックすると、Google Cloud プロジェクトの選択画面が表示されます（API キーは Google Cloud プロジェクトに紐付けて発行される仕組みのため）。
  3. 初めての場合は「新しいプロジェクトで API キーを作成」を選びます。プロジェクト名は自動入力のままで構いません。「API キーを作成」を押すと、Google Cloud プロジェクトが自動的に作成され、続けて API キーが発行されます（Google Cloud Console に別途行ってプロジェクトを作る必要はありません）。
    ※ すでに Google Cloud のプロジェクトをお持ちの方は「既存のプロジェクトから作成」を選んで該当プロジェクトを指定してください。
  4. 発行されたキー（AIza... で始まる文字列）をコピーして安全な場所にメモします。
    ※ このキーはパスワードと同じ扱いです。他人に教えたり GitHub などに公開したりしないでください。

Apps Script へのキー登録

  1. STEP 2 で開いた Apps Script エディタを開きます（作業用 Doc →「拡張機能 → Apps Script」）。
  2. 左サイドバーの「プロジェクトの設定」（歯車アイコン）をクリックします。
  3. 「スクリプト プロパティ」セクションまでスクロールし、「スクリプト プロパティを追加」をクリックします。
  4. プロパティ名に GEMINI_API_KEY、値に取得した API キーを貼り付けて「保存」します。
無料枠の制限について
Gemini 2.5 Flash の無料枠は 分あたり 10 リクエスト・1日 250 リクエスト。半自動モードは問題なく動作しますが、全自動モードで連続実行すると分あたり制限に引っかかる場合があります。その場合はフェーズ間に時間を置くか、半自動モードをお使いください。クレジットカード未登録であれば課金は発生しません。

セキュリティ強化：API トークン（任意）

GAS のデプロイ設定は「全員（匿名）」にする必要があります（Chrome 拡張から fetch する制約のため）。 ただし、Web App URL が漏れた場合に第三者が自分の Doc に書き込めてしまうリスクがあるので、 受講者ごとに「合言葉（API トークン）」を設定して鍵を掛けることができます。任意機能です。設定しなくても動作には問題ありません。

仕組み
① GAS 側のスクリプトプロパティに SK_API_TOKEN を任意の文字列で登録
② 拡張機能のオプション画面の「API トークン」欄に同じ文字列を入力
→ 拡張機能はリクエストごとに自動でトークンを送信。一致しないリクエストは UNAUTHORIZED で弾かれます。

設定手順

  1. 合言葉を決める。20 文字以上のランダムな文字列を推奨（例: nrg-2026-spring-7x9k）。パスワードと同じ扱いで、他人と共有しないでください。
  2. GAS 側に登録。STEP 2 で作った作業用 Doc を開き「拡張機能 → Apps Script」→ 左サイドバーの「プロジェクトの設定」（歯車）→「スクリプト プロパティ」へ。
  3. 「スクリプト プロパティを追加」をクリック → プロパティ名 SK_API_TOKEN、値に手順 1 で決めた合言葉を入れて「保存」。
  4. 拡張機能側に登録。Chrome のツールバーから STRATEGY-KIT のオプション画面を開き、「API トークン（任意）」欄に手順 1 と同じ合言葉を入力。
  5. 「接続テスト」を実行。成功すれば認証付きで動いています。失敗した場合は GAS 側と拡張機能側のトークンが完全一致しているか確認（前後の空白・全角半角に注意）。
注意： トークンを忘れた・無効化したい場合は GAS 側のスクリプトプロパティから SK_API_TOKEN を削除すれば認証なしの動作に戻ります（拡張機能側の入力欄も空にしてください）。

よくある詰まりポイント

トークンを設定したら接続テストが通らなくなった
GAS 側と拡張機能側のトークンが完全一致しているか再確認。前後の空白、全角／半角、コピペ時の改行混入が原因のことがほとんどです。両方を一度クリアして、同じ値を再貼付するのが確実。
トークンを設定すべき？スキップしてもいい？
受講者数十名の限定配布で実害は低いのでスキップして OK。ただし Web App URL を Slack や LINE で共有してしまった経験がある／心配性の方は設定推奨です。

困ったら（よくある質問）

Q1「STRATEGY-KIT」メニューが表示されない
以下の順で確認してください:
  1. ブラウザのタブを完全に閉じて開き直す（再読み込みだけでは不足な場合があります）
  2. Apps Script エディタで Code.gs に shim が保存されているか確認（STEP 2 を再確認）
  3. 左サイドバーに StrategyKitLib ライブラリが表示されているか確認
Q2「StrategyKitLib is not defined」というエラーが出る
ライブラリの追加が正しく完了していません。STEP 2 に戻り、Apps Script エディタ左サイドバーの「ライブラリ」欄に StrategyKitLib が表示されているか確認してください。表示されていなければライブラリ追加をやり直します。スクリプト ID のコピーミスが最多原因です。
Q3「権限がありません」と表示される
Web App デプロイ時の OAuth 承認が完了していない可能性があります。STEP 3 に戻り、「デプロイ → デプロイを管理」から最新のデプロイを選び、権限承認を最後まで通してください。「詳細 → （アカウント名）に移動」のリンクをクリックするところまで進む必要があります。
Q4「Google で確認されていません」警告が表示される（対処の詳細）
受講者自身がデプロイした自作アプリのため、この警告は必ず表示されます。正常な動作です。以下の手順で通過してください:
  1. 警告画面の下部「詳細」をクリック（小さい文字のリンクです）
  2. 「（自分のアカウント名）に移動（安全ではないページ）」をクリック
  3. 「アクセスを許可」をクリックして承認を完了
「キャンセル」や「戻る」を押すと承認が通らず、ツールが動作しません。
Q5全自動モードが途中で止まる
Gemini 無料枠の「分あたり 10 リクエスト」制限に引っかかっています。フェーズとフェーズの間に 1〜2 分待ってから再実行してください。または半自動モードに切り替えると1プロンプトずつ手動実行になるため制限に引っかかりません。
Q6テンプレート Doc が壊れた（編集してしまった）
テンプレート原本 Doc を直接編集してしまった場合は、配布物の template_v3.0.md から再度 STEP 1 の手順でテンプレート原本 Doc を作り直し、STEP 6 の「テンプレート原本セットアップ（初回のみ）」を再実行してください。これまでの既存の案件 Doc には影響しません。
Q7Chrome 拡張のアイコンがグレーアウトしている
chrome://extensions/ を開いて STRATEGY-KIT Helper が「有効」になっているか確認してください。「デベロッパーモードの拡張機能を無効にしますか？」のポップアップで「無効にする」を押してしまった場合は、ここで再度有効化できます。
