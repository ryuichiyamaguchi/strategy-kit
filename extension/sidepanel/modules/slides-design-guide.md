# STRATEGY ROUTE — Visual Design Guide

> **このファイルはスライド本文ではなく、NotebookLMに読み込ませるブランドブックです。**
> 内容を要約したり、1章としてスライド化したりしないでください。
> Slide Deck生成時の配色・文字・余白・図解・レイアウト判断に一貫して適用します。

---

## 0. デザインの一文定義

**「戦略の現在地と、次に進む航路が一目で分かる意思決定資料」**

読み手は店舗オーナー、経営者、支援者、金融機関担当者を想定する。
見栄えのために情報を飾るのではなく、次の3点を視覚化する。

1. いま何が分かっているか
2. どの選択肢を採用するか
3. 次に何を、いつまでに実行するか

資料全体の固有モチーフは **Route Rail（航路ライン）**。
§0〜§9を10個のWaypointとして細い線でつなぎ、現在章だけを強調する。
単なる装飾ではなく「戦略立案のどこを説明しているか」を示すナビゲーションとして使う。

## 1. ビジュアル・テーゼ

### 1-1. 基本リズム

- **章扉**: Deep Routeの濃紺背景。大きな章番号と1文の結論。
- **本文**: Route Mistまたは白背景。結論・根拠・次の行動を整理。
- **数値**: 余白の中に大きく置き、表より先に読ませる。
- **図解**: データや因果関係を説明するときだけ使う。
- **締め**: 決定事項と次の一手をDeep Route背景で再提示する。

全スライドを同じカードレイアウトにしない。
「濃紺の章扉 → 明るい結論 → 根拠 → 図解・数値 → 次章」の呼吸を作る。

### 1-2. この資料だけのシグネチャー

章扉では、右端に **180〜220pt相当の章番号**を置き、15〜25%だけ画面外へ切る。
章番号は白の8〜12%濃度、本文は左側に寄せる。
下端には10地点のRoute Railを通し、現在地点をWaypoint Mintで光らせる。

大胆さは章扉と主役の数値に限定する。本文スライドまで装飾過多にしない。

## 2. カラーシステム

| Token | HEX | 役割 |
|---|---|---|
| Deep Route | `#10233D` | 章扉、最終結論、本文文字 |
| Route Blue | `#3E72E8` | 現在地、比較対象、リンク、主系列 |
| Waypoint Mint | `#53C8BF` | 採用案、到達点、成功状態、Route Rail |
| Signal Amber | `#F1A84A` | 未確定、リスク、注意、判断待ち |
| Route Mist | `#F5F7FA` | 本文背景、表の薄い帯 |
| White | `#FFFFFF` | 章扉文字、明るいカード面 |

### 使用比率

- White / Route Mist: **65〜75%**
- Deep Route: **18〜25%**
- Route Blue + Waypoint Mint: **合計8〜12%**
- Signal Amber: **3%以下**

### 色の判断規則

- 最重要の結論・本文 → Deep Route
- 現在地・比較の主系列 → Route Blue
- 採用済み・目標到達・推奨 → Waypoint Mint
- リスク・未確定・要確認 → Signal Amber
- 出典・補足 → Deep Routeの60〜70%濃度

Waypoint MintとSignal Amberは白背景の小さい文字色に使わない。
色だけで状態を伝えず、必ず「採用」「要確認」「保留」などのラベルを添える。

### 禁止色

- 紫〜ピンクのAI風グラデーション
- ネオンカラー
- 目的のない多色使い
- 赤と緑だけで良否を伝える配色

## 3. タイポグラフィ

| 役割 | 推奨 | サイズ目安 |
|---|---|---|
| 章扉・表紙 | BIZ UDPGothic 700 | 30〜42pt |
| スライド見出し | BIZ UDPGothic 700 | 24〜30pt |
| 本文 | Noto Sans JP 400 / BIZ UDPGothic 400 | 15〜18pt |
| 数値 | JetBrains Mono 600 / Roboto Mono 600 | 34〜64pt |
| 注釈・出典 | Noto Sans JP 400 | 10〜12pt |

- 日本語見出しは20字以内を目安にする。
- 見出しを名詞だけで終わらせず、可能なら結論文にする。
  - 弱い例: 「顧客分析」
  - 強い例: 「平日夜の初心者が、継続率を押し上げる」
- 1スライド内の太字は3箇所以内。
- 数字と単位のサイズに差をつける。数字を主役、単位を補助にする。
- 長文を小さくして収めない。削るか、スライドを分ける。

---

## 4. グリッドと余白

- 画面比率: **16:9**
- 外側余白: 左右64〜80px、上下48〜64px相当
- 12カラムグリッドを基本にする
- 要素間隔は8の倍数（16 / 24 / 32 / 48）を優先する
- タイトルと本文の間は最低24px相当
- 本文行間は1.45〜1.6

### 非対称レイアウト

毎回50:50に分けない。結論と根拠の強さに合わせ、次を使い分ける。

- **7:5** — 結論 + 図表
- **8:4** — 大きな数値 + 条件
- **5:7** — 前提 + 比較表
- **全幅** — 章扉、ロードマップ、マトリクス

---

## 5. Route Rail（航路ライン）

Route Railは§0〜§9の10地点を一本の線で結ぶ。

```text
§0 ●──○──○──○──○──○──○──○──○──○ §9
    現在地
```

- 未到達: Deep Route 20%濃度の細線と中空点
- 通過済み: Route Blueの実線と小さい実点
- 現在地: Waypoint Mintの大きい点 + 章名
- 次の一手: 現在地の右隣だけ短いRoute Blueライン
- 章扉では下端、本文では右上に小さく配置してよい
- すべての本文スライドへ大きく繰り返さない

## 6. 使うスライド型

### A. Cover / 表紙

```text
┌────────────────────────────────────┐
│ STRATEGY ROUTE                     │
│                                    │
│ 事業名                             │
│ マーケティング戦略 2026            │
│                                    │
│ ──●──○──○──○──○──○──○──○──○──○  │
└────────────────────────────────────┘
```

- Deep Route背景
- タイトルは左下寄せ
- 事業名、資料名、日付、対象者だけ
- 写真を使う場合は、事業固有の実写1枚を大きくトリミングする

### B. Chapter Gate / 章扉

```text
┌────────────────────────────────────┐
│ §4                                 │
│                                    │
│ 勝ち筋を3施策に絞る                 │   04
│ 採用理由を1文で                     │
│                                    │
│ ──●──●──●──●──●──○──○──○──○──○  │
└────────────────────────────────────┘
```

- Deep Route背景
- 左側に章名と1文の結論
- 右端に画面外へ切れる巨大な章番号
- Route Railで現在地を表示

### C. Decision / 結論スライド

- 左7カラム: 24〜30ptの結論文
- 右5カラム: 根拠3点または数値1点
- 上部に小さく「DECISION」「EVIDENCE」「NEXT」など役割ラベル
- 結論を箇条書きの中に埋めない

### D. Big Number / 数値スライド

```text
┌────────────────────────────────────┐
│ 最重要KPI                          │
│                                    │
│       1,200                         │
│       会員 / 2027年3月              │
│                                    │
│ 現状 840  →  差分 +360              │
└────────────────────────────────────┘
```

- 1スライドに主役の数値1つ。比較が必要なら最大3つ
- 数値はDeep RouteまたはRoute Blue
- 目標到達状態だけWaypoint Mintの帯・点で示す
- 期間・前提・出典を必ず添える

### E. Evidence → Implication / 根拠と示唆

- 左: 出典付き事実、顧客の声、調査数値
- 右: その事実から導く判断
- 中央に細い矢印またはRoute Line
- 「事実」と「解釈」を同じ箱へ混ぜない

### F. Priority Matrix / 優先度

- 縦軸: インパクト
- 横軸: 実行可能性
- 右上をWaypoint Mintの薄い面で強調
- 採用案はラベル付きで最大5件
- 却下案はSignal Amberではなく、Deep Route 40%濃度で残す
- マトリクスの横に「なぜこの3案か」を1文で置く

### G. KPI Dashboard / KPI・ユニットエコノミクス

- 上段: 主役KPIを大きく1つ
- 下段: CAC / LTV / Payback / LTV÷CACを横並び
- 4つを同じ強さにしない。意思決定に効く指標を1つだけ大きくする
- 「現状 / 目標 / 差分 / 期限」を比較できる形にする
- 推定値はレンジ、確定値は単一値。1セル内で混在させない

### H. Roadmap / 実行計画

- 横軸を時間、縦方向に施策または担当を置く
- いま着手する区間だけRoute Blue
- 到達点はWaypoint Mintの菱形または丸
- 依存関係は細線でつなぐ
- 「今週」「30日」「90日」の3段階を優先する

### I. Decision Log / 決定ログ

- 「採用」「見送り」「保留」の3列
- 各項目は 決定 / 理由 / 見直し条件 を1セットにする
- Signal Amberは保留ラベルだけに使用
- 最下部に「次に見直す日」を1行で置く

## 7. 章ごとの見せ方

| 章 | 主役 | 推奨スライド型 |
|---|---|---|
| §0 ゴール | 期限付き数値目標 | Chapter Gate + Big Number |
| §1 顧客 | 行動・課題・選定理由 | Evidence → Implication |
| §2 提供価値 | 顧客課題と解決価値 | Decision + Before/After |
| §3 課題 | 解くべきボトルネック | Evidence → Implication |
| §4 戦略 | 採用する勝ち筋 | Priority Matrix + Decision |
| §5 戦術 | 具体施策とチャネル | 施策ポートフォリオ + Roadmap |
| §6 体制 | 誰がいつ動くか | Responsibility Map + Roadmap |
| §7 KPI | 現状・目標・採算 | KPI Dashboard + Big Number |
| §8 リスク | 発生条件と対応 | Signal Table |
| §9 決定ログ | 採用・見送り・保留 | Decision Log |

## 8. 図解・グラフ・画像

### 図解

- 因果: 左から右
- 階層: 上から下
- 時系列: 左から右
- 比較: 同じ基準・同じ縮尺
- 1図解のノードは7個以内

### グラフ

- 棒グラフ: 項目比較
- 折れ線: 時系列
- ウォーターフォール: 増減要因
- 散布図: 優先度・相関
- 円グラフは3区分以内で、構成比を示す必要がある場合だけ

チャートは主系列をRoute Blue、採用目標をWaypoint Mint、その他をDeep Route 20〜35%濃度にする。
3Dグラフ、メーター乱用、根拠のない装飾グラフは禁止。

### 画像

- 事業固有の実写、商品、店舗、顧客接点の画像を優先する
- ソースに画像がない場合は、Route Rail、地図、シンプルな幾何図形で構成する
- 握手、会議室、空を見上げる人物などの汎用ストック写真は禁止
- AI人物画像を実在顧客のように扱わない
- 1スライド1ビジュアルを上限の目安にする

## 9. Presenter Slides と Detailed Deck

### Presenter Slides

- 1スライド1メッセージ
- 本文3〜5点、各行35字以内を目安
- 大きな数値、図解、比較を優先
- 説明の詳細は読み上げ原稿へ回す

### Detailed Deck

- 単体で読んでも理解できる説明量
- 本文は最大7点まで。ただし段落を並べず、見出しで分割する
- 出典、前提、判断理由を省かない
- 小さな文字で詰め込まず、必要ならスライドを分ける

---

## 10. 禁止事項

- 全ページを同じ3カード構成にする
- 角丸カードの中へさらにカードを入れる
- 紫・ピンク・青のAI風グラデーション
- 意味のない光彩、ガラス表現、強いドロップシャドウ
- タイトルの下に長文をそのまま貼る
- 1スライドに複数の結論を詰め込む
- 数値を出典・期間・単位なしで見せる
- 「革新的」「最適」「圧倒的」など、根拠のない形容詞を大見出しにする
- すべての要素を中央揃えにする
- すべてのスライドへ写真やアイコンを置く

## 11. 配布前の品質ゲート

- [ ] 表紙を見て、事業名・目的・対象者が5秒で分かる
- [ ] 各章扉に1文の結論と現在地がある
- [ ] スライド§0で「いつまでに・何を・いくつ」が読める
- [ ] スライド§4で採用施策と採用理由が分かる
- [ ] スライド§7で現状・目標・差分・期限が比較できる
- [ ] 事実・仮説・決定が視覚的に混ざっていない
- [ ] 未確定値には「要確認」と見直し条件がある
- [ ] ◯ / △ / ★貼付★ / 空欄が残っていない
- [ ] 出典とページ番号が小さくても読める
- [ ] Route Railが装飾ではなく現在地を示している
- [ ] 同じカード型が3枚以上連続していない
- [ ] PDF書き出し後に文字切れ・重なりがない
