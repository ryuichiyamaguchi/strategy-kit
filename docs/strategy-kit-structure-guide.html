まず結論

原本はコピー元

テンプレート原本 Doc は、案件用マスターを作るための型です。基本的にここへ作業結果を書き込みません。

書き込みはGAS経由

Chrome拡張はGoogle Docsを直接編集するのではなく、登録されたGAS Web App URLへ依頼します。

本体ロジックはライブラリ

受講者が貼るGASは薄い窓口です。実際の処理は山口さん管理の StrategyKitLib が担当します。

登場人物

同じ「テンプレート」「GAS」という言葉でも役割が違います。ここを分けると全体像が見えやすくなります。

何をいじると、どこに書き込まれるか

日常運用で迷いやすい操作だけを、書き込み先ベースでまとめます。

操作 触る場所 保存・書き込み先 意味
テンプレート原本セットアップ Docメニュー または GAS action setupTemplate SK_TEMPLATE_DOC_ID 「どのDocを原本としてコピーするか」をGASが覚えます。原本文面は書き換えません。
新規マスタードキュメント作成 Docメニュー または createMasterFromTemplate 新規マスターDoc SK_DOC_ID 原本を makeCopy() し、{{店舗名}} などを replaceText() で差し替えます。
拡張機能にGAS URLを登録 Chrome拡張のOptions chrome.storage.sync gasWebAppUrl_v10 拡張機能がどのGASへ依頼するかを覚えます。Google Docs本文には書き込みません。
業種・店舗名などを入力 Chrome拡張サイドパネル chrome.storage.sync と §-1 案件メタ情報 設定として保存し、GAS URLがある場合は appendMeta でマスターまたはDRAFTの§-1へ反映します。
プロンプト挿入 Chrome拡張サイドパネル AIサイトの入力欄 Claude / ChatGPT / Geminiなどの入力欄へ入れるだけです。送信やDoc保存は人の確認を挟みます。
全自動モード Chrome拡張サイドパネル [DRAFT] Doc SK_DRAFT_DOC_ID geminiProxy で生成し、appendDraftSection でDRAFTへ追記します。マスターDocは直接汚しません。
§N 要点版を追記 Docメニュー または appendSectionSummary マスターDocの該当§ 後続フェーズが参照しやすいよう、章末の「§N 要点版」を追加または置換します。
決定ログ追記 Docメニュー または 拡張の決定ログ機能 マスターDocの§99 意思決定、理由、次アクションを1行で残します。
リサーチ保存 拡張機能 Driveのresearchフォルダ マスターDocと同じフォルダに research-*.md を作ります。
CLEAN / SUMMARY 作成 GAS action [CLEAN] Doc [SUMMARY] Doc DRAFTを整形した別Doc、または要約Docを新しく作ります。元のマスターとは別ファイルです。

更新の伝わり方

「何を更新したら、受講者側に反映されるか」は場所ごとに違います。

テンプレート原本を直した場合

次に createMasterFromTemplate で作る新規マスターに反映されます。すでに作成済みのマスターDocには自動反映されません。

StrategyKitLibを直した場合

shim側が developmentMode: true なので、受講者のGAS窓口から呼ばれる処理が更新後のライブラリになります。

Chrome拡張を直した場合

サイドパネル、設定画面、プロンプト、GAS呼び出し方が変わります。受講者は拡張機能の更新版を読み込み直します。

覚え方: 原本は「コピーされる紙」、GASシムは「受付窓口」、StrategyKitLibは「中で作業する人」、拡張機能は「操作リモコン」です。

初期セットアップの流れ

1

テンプレート原本 Doc を用意します。これは章構造と差し替え欄を持つコピー元です。

2

作業用Docを開き、Apps Scriptにshimの Code.gs を貼ります。appsscript.json では StrategyKitLib ライブラリを参照します。

3

Web Appとしてデプロイし、発行されたURLをChrome拡張Optionsの gasWebAppUrl_v10 に保存します。

4

Docメニューの「テンプレート原本セットアップ」で原本DocのURLを登録します。GASは SK_TEMPLATE_DOC_ID として覚えます。

5

案件ごとに「新規マスタードキュメント作成」を実行します。原本をコピーし、案件名などを差し替えたマスターDocができます。

事故を防ぐ注意点

テンプレート原本では作業メニューを実行しない

原本に作業結果を書いてしまうと、次に作る全案件の型が汚れます。原本はコピー元として扱います。

GAS URLの登録先を間違えない

拡張機能は gasWebAppUrl_v10 に保存されたURLへ依頼します。別案件のGAS URLを入れると別Docへ書く可能性があります。

DRAFTは安全な下書き場所

全自動モードの出力は [DRAFT] Doc に追記されます。人が確認してからマスターへ採用します。

ライブラリ更新とテンプレ更新は別物

ライブラリ更新は動き方、テンプレ更新は新しく作るDocの型に効きます。既存Docの本文は勝手に差し替わりません。
